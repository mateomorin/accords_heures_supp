# How to use embed chunks?

To be able to run the data conversion script `embed_chunks.py`, you need several requirements:

- proper data storage
- LLM connected with an API compatible with OpenAI
- Qdrant vector data storage
- time

## Data storage

The first main requirement is data storage. This project was built using Insee's [SSP Cloud](https://datalab.sspcloud.fr/), which storage relies on MinIO (S3-like storage system). Thus, if you do not use S3, you need to change everything that uses `s3fs.S3FileSystem()`. Good luck (still possible though).

Then, you need to make sure of your storage organization:

- All your data must be stored in parquet files located in folder `FULL_DATA_PATH` (from `config.py`). Then you will just need to give the desired themes before RAG implementation (all by default). The data must at least contain these fields:
  1.  Column `id`, unique reference made to the document taken from Legifrance (like `cid`),
  2.  Column `dateSignature`, chains of characters in datetime format such that conversion is easy,
  3.  Column `dateDiffusion`, chains of characters in datetime format such that conversion is easy.
  4.  Columns `YYYY` and `MM` , representing years and months of signature in format `:04d` and `:02d`.
- The script was designed to process shards generated by the docx to markdown script of [this repository](https://github.com/mateomorin/scrapping_accords/). Its output is a folder containing different subfolders (1 per year) of format `acco_data_YYYY/`, each of them containing shards of format `shard_XXXXX.parquet`. If you do not have a structure like that, you might struggle running the main script.

## Running the main script

The main script is `src/rag/embed_chunks.py`. It relies on a config file ``` src/``rag``/config.py ``` that is meant to be changed depending on your set up and your needs.

A usual set up for a new user would be like this:

- Clone repository:

```{bash}
git clone https://github.com/mateomorin/accords_heures_supp.git
cd scrapping_accords
```

- Install dependencies with uv:

```{bash}
pip install uv
uv sync
```

- Configure the `src/rag/config.py` according to your needs. Especially, make sure to change all the variables linked to paths and to provide the correct LLM/Qdrant APIs.

- Configure your `.env` file to set `LLM_API_URL`, `LLM_API_KEY` and potentially `QDRANT_API_KEY` (or use `export` command in bash terminal). You can use `.env.example` as a template (no need to configure the Legifrance API variables).

- Then run the script to convert your files:

```{bash}
uv run src/rag/embed_chunks.py --data_folder acco_data_2018 --themes "Heures supplémentaires (contingent, majoration)" --collection accords_heures_supp
```

- 

  - `data_folder`: name of the folder in `FULL_DATA_PATH`, e.g. `acco_data_2018`,

  - `themes` (optional): filter by a specific theme in the dataframes (default: all),

  - `collection` (optional): name of the collection to store chunks in Qdrant

## Using Argo Workflows

If you want to go faster in the process, you can use argo workflow. Just be careful of the concurrency management in the config file, especially because you might spend a lot of tokens (and I mean really a LOT of tokens) quickly. On the other hand, if your server that hosts a LLM is too small, you might receive errors. Thus, you need to find compromises between speed/cost monitoring/server capabilities.

The script that almost fits you is located in `src/rag/argo_chunk.yaml`, just make sure to create your own secrets so that everything works well. Change the number of parallel pods if necessary.
